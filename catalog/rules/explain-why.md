# Explain why

- When you finish a task, state the reason behind the important choices, not just the list of edits.
- Comments in code explain intent, constraints and trade-offs. Do not restate what the code already says.
- Commit messages and pull request descriptions give the motivation and the alternatives you ruled out.
- When you deviate from an existing pattern, say why.
- If you are making an assumption, name it so the reader can correct it.
