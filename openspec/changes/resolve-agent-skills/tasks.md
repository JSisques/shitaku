## Reconciliations (spec vs design; the spec wins)

Applied in the tasks below. The design text is superseded where it differs.

- R1. Flow list trailing comma: spec accepts a single trailing comma (`[a, b,]`) and rejects a double one (`[a,,]`); design rejected any trailing comma. Follow the spec (task 1.3).
- R2. Duplicate `skills:` key in one frontmatter is rejected with a key-named issue (spec only; design silent). Task 1.3.
- R3. Reader rejection issues must name the key AND the offending line (spec); design only named the key. Double-quote escapes other than `\\ \" \/ \n \t` advise single quotes. Task 1.3.
- R4. Plain scalar `skills: foo` and `skills: a, b` are rejected with a key-named issue (final user decision; closes design open question 1). Task 1.3.
- R5. Both block form (column 0 or indented, consistent indent) and inline flow form are supported (final user decision). Task 1.3.
- R6. Message text: singular `required by agent a`, plural `required by agents a, b`; warning `agent X requires skill Y, which is not in the catalog`; note `agent X requires skill Y, found on disk, not managed by shitaku`. Matches spec and design; the spec owns the text (tasks 2.1, 2.2). Closes design open question 2.
- R7. Messages are carried in `ChangePlan.warnings` and `ChangePlan.notes` (field name `notes`, plain `string[]`), printed as `warning:` / `note:` lines on stdout (tasks 2.4, 3.6).
- R8. Skipping a conflicting auto-added skill while another item is overwritten must not overwrite it: `InitRequest.skippedSkills` (design-only, kept; spec "Auto-added skill conflicts" and re-plan rules require consistent re-planning) (tasks 3.4, 3.5, 3.6).
- R9. A catalog-missing skill present on disk yields a note, not a warning, in run scope, or in user scope when the run scope is project (final user decision; spec scenarios) (tasks 3.1, 3.2).
- R10. Docs scope: proposal limits docs to CONTRIBUTING and README; the website docs update is a follow-up, NOT part of these tasks (closes design open question 3). The spec scenario "Limit documented" is checked in task 4.3 (no doc may claim the old single-line or opaque-skills limit).
