# Proposal: Add docs-writing Catalog Skill

## Intent

Add a bundled **docs-writing** skill (#125) so agents write and maintain project documentation consistently: README structure, CHANGELOG conventions, code comments and JSDoc/TSDoc, keeping docs in sync with code, and a concise, neutral tone. Today agents improvise documentation, which leads to comments that restate the code, hand edits to release-generated changelog sections, and READMEs that drift from behavior. The catalog already ships `pr-writing`; this skill covers the documentation side with the same format and precedent.

## Scope

### In Scope

- `catalog/skills/docs-writing/SKILL.md`: English, generic (works in any repository), model-invocable (no `disable-model-invocation`), single-line `name: docs-writing` and single-quoted, single-line `Trigger:`-style `description` (<=250 chars, no quotes or pipes). Layout mirrors `pr-writing`: Activation Contract, Hard Rules, Decision Gates (table), Execution Steps, Output Contract (~45-65 lines).
- Skill behavior, five areas from issue #125:
  - **README**: purpose first, install, usage, configuration, contributing/license links; follow the existing structure when one exists.
  - **CHANGELOG**: Keep a Changelog format and Conventional Commits mapping; never hand-edit sections generated by a release tool (for example semantic-release); when releases are automated, change commit messages instead of the file.
  - **Comments and JSDoc/TSDoc**: explain why, not what; document public API contracts (params, returns, throws); no commented-out code or stale TODOs.
  - **Sync**: update docs in the same change as the behavior they describe; prefer generated docs and their check scripts when the repository has them.
  - **Tone and style**: concise, neutral, second person or imperative, follow existing repository style and language.
  - Decision Gates: release-generated changelog (do not edit), existing docs generator (run it, do not hand-edit output), existing style guide or template (follow it).
- Register `docs-writing` in `catalog/catalog.json` -> `items.skills` (alphabetical: `docs-writing`, `example-skill`, `pr-writing`, `socratic-method`).
- Update `test/adapters/catalog/bundled-catalog.test.ts` RED first: bundled skill list, directory entries, count 3 -> 4, a `docs-writing` entry with `files: ['SKILL.md']`, and a small content-contract test modeled on the pr-writing one (asserts only a few load-bearing tokens).
- Regenerate docs: `pnpm run docs:catalog` (README) then `pnpm run docs:website-catalog` (website en/es); verify with the matching `:check` scripts.

### Out of Scope

- PR titles and descriptions (owned by `pr-writing`).
- Commit messages.
- Agent behavior and agent instruction files such as AGENTS.md conventions (tracked separately in #126).
- Release notes authored by a release tool.
- Any change to `catalog/skills/pr-writing/SKILL.md` (see Boundary decision below).
- A `references/` folder or multi-file skill (exploration Approach B).
- Any `src/` change (domain, ports, application, adapters) or install-time templating.

### Boundary with pr-writing

`pr-writing` says "Not for commit messages, changelogs, or release notes." That wording is already correct for the new split: changelogs belong to `docs-writing`. Decision: **leave pr-writing unchanged**. `docs-writing` states the reciprocal exclusion ("Not for pull request titles or descriptions, or commit messages"). This keeps the change additive, avoids touching the pr-writing content-contract test and spec, and adds no delta spec.

## Capabilities

Catalog-bundled skill content and installability acceptance. Install/list/validate behavior stays under existing `catalog` and `skills-install` (no deltas). `pr-writing-skill` is not modified.

### New Capabilities

- `docs-writing-skill`: catalog-bundled documentation writing skill content (README, CHANGELOG, comments and JSDoc/TSDoc, docs sync, tone), activation boundary with pr-writing, decision gates, and installability acceptance.

### Modified Capabilities

None

## Approach

Exploration Approach A: a single generic `SKILL.md` mirroring the archived `add-pr-writing-skill` change and CONTRIBUTING "Add a skill". The skill instructs the agent to inspect the repository first (existing README layout, CHANGELOG origin, release config, docs generators, style guides) and then write or update documentation following the five areas. Install remains a byte-identical copy. Strict TDD (`pnpm test`): update the bundled-catalog test first and observe RED, then add the skill and catalog entry (GREEN), then regenerate docs.

Delivery: one PR with two Conventional Commits:

1. `feat(catalog): add docs-writing skill` (SKILL.md, catalog.json, test).
2. `docs: list docs-writing skill in README and website` (generated README and website pages).

## Risks

| Risk                                               | Likelihood | Mitigation                                                                                    |
| -------------------------------------------------- | ---------- | --------------------------------------------------------------------------------------------- |
| 250-char description too tight for five areas      | Med        | Trigger list of short phrases plus one summary clause; count characters in the test or review |
| Frontmatter or website emitter parse failure       | Low        | Single-line, single-quoted description without quotes or pipes; mirror pr-writing             |
| Docs CI drift (README/website out of sync)         | Med        | Run both docs scripts in order and their `:check` variants                                    |
| Brittle content guard                              | Low        | Assert only a few load-bearing tokens (for example Keep a Changelog, JSDoc, why not what)     |
| Overlap or confusion with pr-writing on changelogs | Low        | Reciprocal exclusions in both Activation Contracts; pr-writing already excludes changelogs    |
| Skill grows beyond the compact format              | Low        | Target ~45-65 lines; defer extra detail rather than add `references/`                         |

## Rollback Plan

Revert the PR (or its two commits): remove `catalog/skills/docs-writing/`, the `catalog.json` entry, the test changes, and the regenerated README/website pages (or rerun the docs scripts after revert). No `src/`, manifest or migration impact. Users who already installed the skill can run `shitaku undo` or delete the installed skill directory.

## Dependencies

- Shipped skills-install capability (#15; covered by the existing `skills-install` spec and used by the archived pr-writing change) and the existing catalog docs generators.
- No external dependency.
